### P2 — Runtime lesson metadata still says publication rights are pending

Each of the 12 new lesson JSON records retains `publicUseStatus: "Original lesson adaptation; accountable owner must clear attribution and publication rights before repository publication."` (for example, `apps/web/src/infrastructure/content/13-evidence-load-ledger.json:111` and `.../16-generator-bank-fuel.json:109`). The lesson JSON is loaded as runtime module data (`apps/web/src/infrastructure/content.ts:31-34`), so this stale assertion ships with lesson content even though the visible lesson UI does not render the field. Synchronize/remove this field across all 12 records so source metadata agrees with the documented decision. This is a metadata consistency issue, not an outstanding rights blocker; the source PDF is explicitly absent from the checkout and not independently hashed.

### P2 — Generator fuel source is omitted from its learning-manifest source hashes

The infrastructure record source list in `apps/web/learn-manifest.ts:195-199` hashes the lesson JSON, `screens.ts`, and `scripts/verify_infrastructure.py`, but omits `apps/web/src/infrastructure/fuel.ts`. That file defines the separate fuel input values (`27,000 kW × 48 h × 0.25 L/kWh`) and lesson wrapper (`fuel.ts:3-8`). Both the interactive run (`InfrastructureCourse.tsx:179-185`) and static lesson output (`seo-infrastructure.ts:76-79`) use this file. Changing these public defaults would change the generator fuel example while the generator lesson's published `sourceFiles` list would not name/hash the changed source. Add `fuel.ts` to the generator lesson's provenance list and cover that linkage in the manifest test. The fuel result itself still includes applied inputs and canonical hashes; this finding is specifically about the learning manifest's source-file provenance.
