GitHub Pages success therefore proves only the forwarding deployment, not a v2 custom-domain deployment.

## Required gates and performance limits

Repository release readiness (`docs/engineering/release-readiness.md:7-19`) requires evidence build and verification, Python regression, JS/native and browser suites, installed-package verification, commit-specific Windows/Linux and Python 3.12/3.14 CI, plus a tested static-host artifact with anonymous hashes and JS/Python parity. Contributor setup also calls for Python 3.12+, Node 24 and npm (`CONTRIBUTING.md:24-47`). Relevant commands are in the JSON; among them `python scripts/build_evidence.py --output outputs/evidence`, `python scripts/build_evidence.py --verify outputs/evidence`, `python -m unittest discover -s tests -v`, `npm --prefix apps/web run test:engine`, `npm --prefix apps/web run test:demo`, `python scripts/verify_distribution.py dist --require-web`, and `npm --prefix apps/web run test:demo -- --grep "search pages"`.

The existing first-result regression ceiling is 600,000 decoded bytes for the explicit advanced 50 MW journey (`docs/engineering/browser-demo.md:27`, `apps/web/tests-demo/course.spec.ts`). The added learning-index JavaScript has a separate 35 KiB gzip ceiling (`docs/engineering/learn-discovery.md:39`, `apps/web/tests-demo/learn-discovery.spec.ts`). Kit targets of 60 fps desktop and a static/30 fps constrained-mobile fallback are proposals, not measured gates. `npm --prefix apps/web run test:demo -- benchmark.spec.ts` records local timing observations, not an SLA.

## Release blockers and rights boundaries

The kit itself says every draft requires an accountable owner's educational-publication and attribution-rights clearance before repository publication (`content/manifest.json`, each lesson's `publicUseStatus`; `release/RELEASE_GATES.md:12,41`). The source PDF is not included and the manifest hash does not confer permission. The repo's Apache-2.0 grant applies to project-owned code and fixtures; preserve `LICENSE`, `NOTICE` and browser-runtime notices, and keep private manuals, private source text, credentials and licensed standards/vendor material out of the public tree (`README.md:133-135`, `CONTRIBUTING.md:76`). A software release cannot lift the manuscript's engineering HOLD or imply certification.

Before v2 publication, the integration still needs production routes/scenes and reading notes, distinct versioned result hashing without changing schema-1/2 behavior, complete base-plus-new CI, accessibility/responsive/performance evidence, owner publication clearance, immutable tag/release/checksum receipt, and authorized Cloudflare deployment plus served-artifact smoke tests. Kit release gates correctly distinguish configured checks from executed evidence.

Skipped: no repository tests, builds, shared-runtime actions, Cloudflare account inspection, or production-domain fetch was performed. Risk: public-use clearance and the authoritative custom-domain deploy/rollback identity remain unresolved.
